This represents **local process** readiness, not any optional DB/Redis dependencies. Axum's existing graceful shutdown allows an in-flight request to finish; without an application timeout, arbitrary long-lived requests can extend shutdown, so a later K8s termination budget must be configured explicitly. The future Linux container manifests must set `YETLET_HOST=0.0.0.0`, `YETLET_PORT=8080` themselves; this profile does not implicitly expose the application.

This failure remains historical and is **not** overwritten.
