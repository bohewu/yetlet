# yetlet-request-id

**Experimental `0.9.0-alpha.1`, unpublished.** Requires Rust 1.99 or newer. This is one of Yetlet's sixteen library candidates; use the local checkout rather than assuming a registry release. APIs are pre-public, and bounded prototype verification is not production qualification.

`yetlet-request-id` adds explicitly installed process-local numeric request correlation to an Axum/Yetlet app. It depends on Axum and `yetlet-server-axum` and has no browser dependency. An app that does not select it allocates no provider counter.

## Install a scoped provider

This example is copied verbatim from the existing `RequestIds::scoped` rustdoc:

```rust
use yetlet_server_axum::{App, extract::Extension};
use yetlet_request_id::{RequestId, RequestIds};
async fn item(Extension(id): Extension<RequestId>) -> String { id.0.to_string() }
let app: axum::Router = App::new().group("/api", |api| {
    api.get("/item", item).configure(|api| RequestIds::new().scoped(api))
}).into_router();
```

`scoped` applies only to already registered routes in the group. For a pre-routing boundary covering the completed app, use `RequestIds::global(app)` as the final router construction step; adding routes to the returned outer fallback router bypasses that boundary.

The complete [REST application](../../examples/rest-api/src/lib.rs) shows correlation beside ordinary handlers. From the repository root:

```bash
cargo run --locked -p yetlet-rest-api
```

Follow [REST's route guide](../../examples/rest-api/README.md) and inspect the `x-yetlet-request-id` response header.

## Lifetime and limits

Clones share one atomic counter; independently constructed providers do not. IDs are generated by the server and overwrite an untrusted inbound correlation value. `Extension<RequestId>` gives typed handler access. The middleware reads/buffers no body and holds no lock across `await`.

`try_new(first)` rejects zero and `u64::MAX` with `InvalidStart`. Allocation refuses overflow and returns HTTP 503 when capacity is exhausted. IDs are not globally unique, persistent, secret or authentication tokens; distribution, trace propagation and logging policy belong to the app. Process restart resets ordinary provider state. See [extension composition](../../docs/EXTENSIONS.md).
