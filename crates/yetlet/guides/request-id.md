# yetlet::request_id

**Experimental SDK module.** Requires Rust 1.99 or newer. Included in
`yetlet` SDK `0.9.0-alpha.8`; this guide describes the selected package contents.
Read source/rustdoc at the revision you consume; package selection does not
establish registry availability or production qualification.

`yetlet::request_id` adds explicitly installed process-local numeric request correlation to an Axum/Yetlet app. It depends on Axum and `yetlet::server_axum` and has no browser dependency. An app that does not select it allocates no provider counter.

## Install a scoped provider

This example is copied verbatim from the existing `RequestIds::scoped` rustdoc:

```rust
use yetlet::server_axum::{App, extract::Extension};
use yetlet::request_id::{RequestId, RequestIds};
async fn item(Extension(id): Extension<RequestId>) -> String { id.0.to_string() }
let app: axum::Router = App::new().group("/api", |api| {
    api.get("/item", item).configure(|api| RequestIds::new().scoped(api))
}).into_router();
```

`scoped` applies only to already registered routes in the group. For a pre-routing boundary covering the completed app, use `RequestIds::global(app)` as the final router construction step; adding routes to the returned outer fallback router bypasses that boundary.

The complete [REST application](https://github.com/bohewu/yetlet/blob/master/examples/rest-api/src/lib.rs) shows correlation beside ordinary handlers. From the repository root:

```bash
cargo run --locked -p yetlet-rest-api
```

Follow [REST's route guide](https://github.com/bohewu/yetlet/blob/master/examples/rest-api/README.md) and inspect the `x-yetlet-request-id` response header.

## Lifetime and limits

Clones share one atomic counter; independently constructed providers do not. IDs are generated by the server and overwrite an untrusted inbound correlation value. `Extension<RequestId>` gives typed handler access. The middleware reads/buffers no body and holds no lock across `await`.

`try_new(first)` rejects zero and `u64::MAX` with `InvalidStart`. Allocation refuses overflow and returns HTTP 503 when capacity is exhausted. IDs are not globally unique, persistent, secret or authentication tokens; distribution, trace propagation and logging policy belong to the app. Process restart resets ordinary provider state. See [extension composition](https://github.com/bohewu/yetlet/blob/master/docs/EXTENSIONS.md).
