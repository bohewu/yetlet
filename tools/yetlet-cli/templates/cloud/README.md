# @NAME@

Unpublished opt-in Yetlet native SSR cloud profile (`native-ssr-v1`). Requires
Rust/Cargo 1.99 or newer and the selected local framework checkout. Uses ordinary
handler-first Axum/Tower with App/Page/View, strict CSP and escaped HTML. No
JS/WASM, Controller, DI, external service or persistent event circuit is required.
This profile is not production qualification or a deployment action.

From this project's parent directory, explicitly resolve this application's own
lockfile from cached dependencies, then check and run:

```sh
cargo generate-lockfile --offline --manifest-path @NAME@/Cargo.toml
cargo check --frozen --manifest-path @NAME@/Cargo.toml
cargo run --frozen --manifest-path @NAME@/Cargo.toml
```

`new --cloud` runs no subprocess, downloads nothing and creates no Cargo.lock.
Keep this application's own lockfile; do not copy a framework/CLI lockfile.
Missing cached dependencies require separate provisioning. The generated absolute
local framework dependency paths must be updated, with an explicit offline lock
refresh, if the checkout moves. Nothing is fetched from Git or a Yetlet registry.

## Bind contract

By default visit http://127.0.0.1:3000/ or /hello/World. `YETLET_HOST` accepts only
the literal IPv4 addresses `127.0.0.1` (default) and `0.0.0.0` (explicit external
listen). Hostnames, IPv6, whitespace, empty and non-Unicode values are rejected.
`YETLET_PORT` defaults to `3000`; an override must contain ASCII decimal digits
and represent 1 through 65535. Invalid values fail startup without echoing them.

Later container manifests must explicitly set `YETLET_HOST=0.0.0.0` and
`YETLET_PORT=8080`. This template does not select them implicitly. Application
operators own network exposure and reverse-proxy TLS/ingress. No writable app
filesystem or privileged port is needed for the default/configured 8080 port;
the runtime is compatible with non-root operation.

## Application-owned health and termination

`GET /health/live` returns HTTP 200 with an empty body. `GET /health/ready` returns
empty-body HTTP 200 while the local process is serving and HTTP 503 once a
shutdown signal is observed. Neither endpoint reveals configuration or secrets.
Readiness describes only this process; it does not establish DB/Redis readiness.
Add real dependency/business readiness policy in the application's `ready` handler
when the application needs it.

Linux/Unix SIGTERM and portable Ctrl-C initiate Axum `with_graceful_shutdown`:
readiness becomes unavailable, the listener stops accepting connections and
in-flight requests may finish before the process exits. During drain a probe may
receive 503 on a surviving connection or a refused/closed connection; a new HTTP
503 response is not promised after the listener closes. A failure to install the
Ctrl-C handler also initiates shutdown. No homemade transport or process manager
is included.

Axum waits for in-flight requests without an application-imposed deadline.
Application operators must bound long requests/streams and choose a later
deployment `terminationGracePeriodSeconds` budget that covers traffic withdrawal
and drain; a forced stop at that deadline can interrupt unfinished work. The
Yetlet CLI `dev` supervisor has its own bounded process cleanup and is not a
production drain supervisor. Test production termination against the directly
launched application binary.

The Cargo metadata marker `[package.metadata.yetlet] cloud-profile =
"native-ssr-v1"` identifies this opt-in bind/health/shutdown contract for later
generators. It is an app-owned declaration, not proof that edited application
source still implements it. No Dockerfile, Compose or Kubernetes manifest is
generated by this command.

On Windows use native Cargo/PowerShell and a protected local fixed NTFS project.
The existing unpublished CLI `build`/`dev` commands require a trusted
owner-protected Cargo executable; interactive `dev` also requires a processed-input
console and owns a Job Object for bounded cleanup. GNU linkers may require an
ASCII `CARGO_TARGET_DIR`. Native GNU/MSVC cloud runtime validation is separate
from Linux evidence.
