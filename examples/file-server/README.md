# File Server — Bounded Native Uploads and Downloads

This local-only application composes native Axum Multipart, Tower HTTP `ServeFile`, Tokio file streams and `tempfile`. It adds no Yetlet storage provider, ORM, Session, browser runtime or replacement HTTP stack.

## Run

From the repository root:

```bash
cargo run -p yetlet-file-server
```

It binds `127.0.0.1:3006`. `YETLET_FILES_LISTEN` may select another **loopback** IP/port; wildcard and non-loopback addresses fail before serving. Native IPv4 and IPv6 loopback parsing is tested; the retained network smoke runs on IPv4/Linux.

Without `YETLET_FILES_TOKEN`, the server creates a random 256-bit development bearer token and prints it **once to its local terminal**, never to HTTP. Keep that output private. Alternatively, set `YETLET_FILES_TOKEN` to your own 64 hexadecimal characters before starting. This is one process-local development capability, not user authentication, permissions or a production credential service.

## Routes and commands

| Route | Contract |
|---|---|
| `/` | English SSR usage page, no JavaScript and no token |
| `/healthz` | Plain `ok`; no Session |
| `/static/welcome.txt` | Exact public static fixture; Tower HTTP GET/HEAD and byte ranges |
| `/uploads` | Bearer-protected POST with exactly one multipart field named `file` |
| `/files/{id}` | Bearer-protected GET/HEAD; opaque ID lookup, never a supplied filesystem path |

Copy the printed token into a private shell variable (do not commit it):

```bash
read -r -s -p 'Development token: ' YETLET_FILES_TOKEN; echo
printf 'Hello from Yetlet.\n' > /tmp/yetlet-example.txt
curl -i -H "Authorization: Bearer $YETLET_FILES_TOKEN" \
  -F 'file=@/tmp/yetlet-example.txt;filename=example.txt;type=text/plain' \
  http://127.0.0.1:3006/uploads
```

The 201 response carries an opaque resource path in `Location`. Use that exact path:

```bash
curl -i -H "Authorization: Bearer $YETLET_FILES_TOKEN" \
  http://127.0.0.1:3006/files/REPLACE_WITH_RETURNED_ID
```

Downloads use `application/octet-stream`, `Content-Disposition: attachment`, `nosniff` and `no-store`. Authenticated downloads intentionally return the full representation and do not implement byte ranges; static fixtures use Tower's range handling. HEAD returns matching metadata with no response body.

## Safety and lifecycle boundaries

- The app creates a fresh temporary root, explicitly mode 0700 at creation on Unix. Only a **fixed bundled welcome fixture** is published through `ServeFile`. There is no arbitrary document root, directory listing or upload-to-static-directory path.
- Upload paths are generated by `tempfile`, never by the submitted filename. Only an ASCII basename ending in lowercase `.txt` is accepted; traversal, separators, extra dots, percent escapes, header metacharacters and other extensions fail closed. Content is checked as streaming UTF-8, rejects binary control characters, and is always downloaded as an attachment. This is not a malware scanner.
- GET/HEAD of uploads and POST mutations require exactly one matching bearer token. Browser `Origin` requests are rejected even with the token; no CORS is enabled. This curl-only fixture does not provide a browser form or cookie/Session CSRF flow.
- Each file is nonempty and at most **1 MiB**. The complete multipart request is limited to **1 MiB + 8 KiB**, exactly one field. **16 files including pending reservations**, **2 concurrent uploads**, **4 active streamed downloads** and a **10-second whole-upload deadline** bound application storage and work. A full store returns 507; capacity is restored by restarting the sample. There is no implicit deletion/overwrite policy.
- A failed parse, extra field, oversized body, invalid text, deadline or task cancellation drops the partial file before it becomes downloadable. The atomic visibility point is insertion after complete parsing and file flush; a client losing the final response may still have successfully committed a complete upload. No automatic retries are performed.
- Each download securely reopens the owned `NamedTempFile`, preserving identity rather than opening a name that might have been replaced with a symlink. It retains file/storage ownership and a concurrency permit until completion or body cancellation. The deliberate same-user symlink-swap regression reads the original file or fails, never reads the replacement.
- `Ctrl-C` drains the server then drops owned files/root. A forced crash/SIGKILL may leave the private temporary directory; crash recovery, external temporary-file cleaners, hostile processes with the same OS identity, deployment-grade HTTP timeouts/TLS and multi-user authorization are outside this sample's assurance. Never deploy it publicly as-is. No persistence across restarts is promised.
